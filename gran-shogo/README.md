# 資料照合（gran-shogo）— グランOS

図面・仕様書（PDF）と建具表・仕上表・見積（Excel）を読み込み、

1. **新旧比較**：同じ資料の変更前と変更後で、変わった文字・数量・金額・数式と図面の線の違い
2. **資料間の照合**：平面図 × 建具表、仕上表 × 見積、設備図 × 見積などで、寸法・数量・品番の食い違いと見積への記載漏れ

を見つけて、**資料名・ページ・セル（根拠）つき**で一覧にするアプリです。最終判断は担当者が行い、確認済みの印とメモを残せます。

- 起動：`start.bat`（または `npm start`）→ http://127.0.0.1:3985/
- はじめての方は画面下の「架空のサンプル資料で試す」から。調査メモの例（W1650/W1600、AA-101/AA-102、照明の見積漏れ、3台/2台）を仕込んであります

## 置き場所とセットアップ

Node.js アプリなので **Google Drive（G:）には置かない**（[[Node系アプリはDriveに置かない]]）。
例：`C:\Users\owner\Documents\Claude\Projects\gran-shogo`

```bat
npm install              :: ライブラリと画面用ファイル（public/vendor）を用意
npm run icons            :: 本家と同じアイコン一式を G:\マイドライブ\その他\グランOS からコピー
copy .env.example .env   :: 必要なら AI照合のキーや合言葉を入れる
start.bat
```

`npm run icons` は、`apple-touch-icon.png`・`icon-192.png`・`icon-512.png`・`icon-512-maskable.png` を本家からコピーします（`logo.svg`・`favicon-32.png`・`sw.js` は同梱済みで、本家とバイト単位で同じことを確認済み）。

## 資料はどこへ行くか（機密の扱い）

| 処理 | どこで | 外部送信 |
|---|---|---|
| PDF・Excel の読み込み、新旧比較、ルール照合、図面の重ね合わせ | ブラウザの中（このPC） | なし |
| 照合の記録（指摘・確認済み・メモ） | `data/runs.json` | なし。資料ファイル自体は保存しない |
| AI照合（チェックを入れたときだけ） | Claude API | **資料の文字だけ**を送る（画像・位置は送らない） |

AI照合は `.env` に `ANTHROPIC_API_KEY` を入れたときだけ選べます。施主名・金額を含む資料を送ってよいかは社内の決まりを確認してください。

## 「いいとこ取り」の対応表

調査した市販ツール・OSSの良いところを、グランOSの中で1画面にまとめています（OSSのコードは取り込まず、考え方だけ参考にしています。diff-pdf は GPL のため）。

| 参考にしたもの | 取り込んだこと | このアプリでの場所 |
|---|---|---|
| Diffchecker / Adobe Acrobat / pdf-diff | 文字の追加・削除・変更を色分け | 新旧比較（PDF）`core/diff.js` `diffPdf` |
| diff-pdf / MIIDEL / Bluebeam Revu | 新旧図面を重ねて色分け、**位置ずれの補正**、変更箇所を枠で囲む | 図面の重ね合わせ `overlay.js` |
| Microsoft Spreadsheet Compare / xlsxDiff | セルの値と**数式**の違い、行・シートの追加削除 | 新旧比較（Excel）`diffXlsx` |
| daff | **記号・品番の列で行を合わせてから**比べる（行が1つずれても全部が差分にならない） | `alignByKey` |
| pdfplumber / Docling | 文字を**位置つき**で取り出し、表を構造化 | `core/readers.js` |
| ChatGPT などの生成AI | 資料をまたいだ意味の矛盾（仕様の反映漏れ） | AI照合 `server/ai.js` |
| （このアプリで足したこと） | AIが挙げた根拠の文言が**本当に資料にあるかを照合**し、無ければ「根拠未確認」 | `verify()` |
| （このアプリで足したこと） | 1文字違いの記号・品番を「品番違いの疑い」として出す | `crossCheck` |
| （このアプリで足したこと） | 図面上の記号の数を数えて、表・見積の数量と比べる | `extractPdf` の `drawnCount` |

## 照合のしくみ（資料間）

1. 各資料から **記号・品番**（AW1、SD-2、DL-1、AA-101…）を拾う。全角・ハイフンのゆれはそろえる（`ＡＷ－１` = `AW1`）
2. Excel は見出し行（記号・品番・W・H・数量・単位…）を探して列の意味を決める。PDF は記号の近く（同じ記入・すぐ下・同じ行の右）にある寸法・数量・名称を拾う
3. 図面（種類＝図面）では、凡例以外に出てくる記号の数を「図面上の数」とする
4. 同じ記号どうしで W・H・数量を比べる → 違えば **不一致**
5. 片方にしかない記号 → 相手が見積なら **記載漏れ（要確認）**、相手側に1文字違いの記号があれば **品番違いの疑い（不一致）**
   - 表・図面どうしは「同じ種類の記号（AW・DL など）を扱っている資料」だけで比べる（建具表に照明が無いのは漏れではないため）
6. AI照合を選んだら、ルールで出した指摘を渡したうえで、それ以外の食い違いだけを探させる

資料の種類（図面／表・仕様書／見積）はファイル名から推定し、画面で変えられます。

## 分かっている限界

- **スキャンPDF（画像だけのPDF）は文字を読めません**。CADから出力したPDFが対象です。OCRは未対応
- 図面の重ね合わせは、照合した画面の中でだけ見られます（資料ファイルを保存しないため、記録から開き直したときは出ません）
- 記号の形が「英字1〜4＋数字」でない書き方（例：「窓1」）は拾えません。会社の記号ルールに合わせて `core/check.js` の `CODE_RE` を足してください
- 見積の「1式」は数量の比較から外しています
