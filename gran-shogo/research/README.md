# 試作：手書き修正の反映チェック

確定打合せで図面に手書きした修正が、実施設計の最新図面に反映されたかを判定する試作（Python・OpenCV・PyMuPDF）。
画面への組み込み前に、実物の図面で精度を確かめるためのもの。**お客様の図面はリポジトリに入れない。**

```
pip install opencv-python-headless pymupdf numpy
python3 proto_reflect.py <手書きスキャンPDF> <打合せ前の版PDF> <打合せ後の版PDF> <出力フォルダ>
```

## しくみ
1. 全ページを画像にする（PyMuPDF。日本語フォントが描けないツールだと、文字がすべて「手書き」に見える）
2. スキャンの各ページに合う「打合せ前の版」のページを特徴点で探し、射影変換＋ECCで重ねる（iPhoneスキャンの台形ゆがみも直す）
3. 手書き＝スキャンにあって打合せ前の版にないもの（色ペン、または版の線から離れた黒）。印刷で太った直線は除く
4. 反映＝手書きの周り（約14mm）で、打合せ前→後の版の「形」か「同じ場所の文字（PDFの文字データ）」が変わったか
5. 指示外の変更＝前→後で変わったのに手書きがない場所

## 実物での結果（2026-11-05・4物件）
正解表は `truth.json`（物件は記号 hi/or/se/nu で表し、お客様の名前は入れていない）、採点は `score.py`。

| 物件 | 手書きスキャン | 打合せ前 → 後 |
|---|---|---|
| hi | 初回（iPhone以外のスキャン） | 前の版 → 約1か月後の版 |
| or | 初回①（iPhoneスキャン19ページ） | 前の版 → 2日後の版 |
| se | 初回① | 前の版 → 5日後の版 |
| nu | 初回③ | 前の版 → 翌日の版 |

- 拾った書き込み78件：指示40件・指示ではない18件（日付・丸付き番号・OK・✓・蛍光での確認・要望メモ）・密で判定できない20件
- **指示40件の反映判定：40件とも正解（100%）**。はじめは画像だけで正解表を付けて4件を「誤り」としていたが、PDFの文字データで確かめると4件ともアプリが正しかった（注記の削除・金物の移動）
- 手書きのないページ（地図・立面図・住設プレゼン）は0件
- 効いた工夫：PyMuPDFでの描画（日本語）、射影変換＋ECC、PDFの文字データでの差分、印刷で太った直線の除外、色の線の変化は蛍光ペンの範囲指定のときだけ数える

## ブラウザ版（2026-11-07・public/js/markup/engine.js）
試作を opencv.js に移し、同じ4物件を画面から通して採点（`score_web.py` の考え方：正解の書き込みの中心を含む箱の判定を見る）。

- **指示40件のうち39件正解**。誤り1件は「反映済み（散水栓の文字の移動）を未反映の疑い」と出したもの（担当者が確かめる側に倒れる誤り）。逆向き（未反映を反映ありと出す）は0件
- 指示ではない書き込み18件のうち8件を「メモ・確認印？」に分けられた（ページの隅・余白の書き込み）。試作では0件
- 図面枠の日付の更新（2026/10/26 → 2026/11/03）は「指示外の変更」から外した
- 処理時間：7〜19ページで27〜69秒（ブラウザの中だけ。ページ探しが約半分）
- しきい値：書き込みの周り60px、変化40px超で反映あり。周りを70pxに広げると、未反映を反映ありと出す誤りが1件出たので60pxのまま

5件目（ya：初回1011＋1026のスキャン）で分かったこと
- スキャンに印刷された版（図面枠の日付 9/24）と、手元にある「打合せ前の版」（10/26）が違うと、すでに直した指示まで「未反映の疑い」に出る。→ 未反映が半分を超えたら、版の日付を確かめる案内を出すようにした
- 印刷した版が残っていないときは、「打合せ後の版」だけで判定するモード（スキャンに印刷された線と比べる・参考）を使う
- 隅の「OK」マーク（各ページ左上）は「メモ・確認印？」に分けられた

## 次にやること
- 指示ではない書き込み（18件：日付・丸付き番号・OK・✓・蛍光での確認）を見分ける（今は「未反映の疑い」に出てしまう）
- 密な書き込み（20件）を1件ずつに分ける（矢印の先・番号ごと）
- 完成形はAPIを使わない（個人開発でコストをかけない）。自動判定は目安として出し、担当者が3枚並びで✓する
- 打合せで使ったPDFを「打合せ用_日付.pdf」として残す運用にする（前の版がないと精度が落ちる）
