# 引き継ぎ書（資料照合 gran-shogo）

2026-11-09 時点。依頼者：松久（社内）。開発は Claude Code で続ける前提。

## このアプリでできること
| 画面 | 何をするか | 状態 |
|---|---|---|
| CHECK（新旧比較） | 同じ資料の変更前・変更後の違い（文字・線・Excel の値と数式） | 動く。**ページを番号順に組み合わせる弱点あり**（課題 1） |
| CHECK（資料間の照合） | 平面図×建具表、見積×図面などの寸法・数量・品番の食い違い | 動く。架空サンプルで4例すべて検出 |
| MARKUP（書き込みの洗い出し） | 打合せの手書きスキャンから指示を拾い、打合せ後の図面に反映されたか判定 | 動く。実物4物件で指示40件中40件正解 |
| RESULT / HISTORY | 指摘の一覧・確認済みの印・メモ・記録 | 動く |

詳しい使い方とファイル構成は `README.md`、MARKUP の実験の経緯と数字は `research/README.md`。

## はじめにやること
1. `cd gran-shogo && npm install && npm test`（12件すべて通ることを確認）
2. `npm start` → http://127.0.0.1:3985/ → 「架空のサンプル資料で試す」
3. テスト用図面を用意して採点（下の「精度の測り方」）

## 精度の測り方（MARKUP）
- 正解表：`research/truth.json`（書き込みごとに R=反映 / N=未反映 / M=指示ではない / U=判定できない）
- 正解表の番号が指す書き込みの位置：`research/e2e/labels/<記号>_boxes.json`（座標だけ。図面は入っていない）
- 図面は Dropbox から取ってきて、リポジトリの外に次の形で置く：
  ```
  <DATA>/hi/scan.pdf  before.pdf  after.pdf
  <DATA>/or/...  <DATA>/se/...  <DATA>/nu/...
  ```
  どの Dropbox ファイルをどこへ置くかの対応表は、**Dropbox の `/★AI成果物★/資料照合_テストデータ対応表.txt`**（施主名が入るのでリポジトリには置かない）。
- 実行：`npm start` を起動したまま `DATA=<DATA> research/e2e/run_labeled.sh`
- 今の結果：`指示 40/40 正解`・`指示ではない書き込みをメモと判定: 8/18`（1回あたり約4分）

## 仕組みの要点（MARKUP）
- ページの組み合わせ：ORB 特徴点（半分の解像度）でスキャンの各ページに合う版のページを探す。打合せ前の版は複数入れられ、一番よく合う版を自動で選ぶ（＝実際に印刷された版）
- 位置合わせ：MAGSAC++（OpenCV の USAC_MAGSAC）で射影変換 → ECC で微調整 → ずれ（px）を両方向で測って表示
- 書き込み：版にない色＋版の線から離れた濃い線。近いものをまとめて1件に
- 反映：打合せ前→後の版で、書き込みの周り（約14mm）の線か PDF の文字が変わったか
- 指示外の変更：前→後で変わったのに書き込みがない場所（日付だけの変化は除く）
- OpenCV.js の注意：`cv` オブジェクトは then を持つので、await したり Promise の値にしたりすると止まる。`{cv}` に包んで渡す（`engine.js` の `loadCv`）。SIFT・FLANN は入っていない
